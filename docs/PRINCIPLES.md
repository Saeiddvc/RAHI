# اصول پایه پروژه راهی

این اصول برای همه Commitها و نسخه‌های بعدی ملاک تصمیم‌گیری هستند.

## ۱. ممنوعیت داده زنده ساختگی

هیچ داده ترافیک، آب‌وهوا، عوارض، قیمت، امتیاز یا وضعیت زنده نباید جعل شود.

در v1:
- Parsimap routing تا زمان endpoint معتبر غیرفعال است
- خط مستقیم جعلی به‌عنوان route تولید نمی‌شود
- Neshan static map به‌عنوان XYZ tile جعل نشده و OSM fallback استفاده می‌شود

## ۲. پیشنهاد Proactive نیازمند Verification Gate

پیشنهاد خودکار مکان، مسیر جایگزین یا توقف باید بر داده معتبر و شروط صریح تکیه کند.

در v1:
- Off-route آستانه 50m دارد
- reroute offer دارای grace period شش‌ثانیه‌ای است

## ۳. تغییر مسیر بدون تأیید کاربر ممنوع

مسیر فعال نباید بدون تصمیم کاربر جایگزین شود.

در v1:
- Timer فقط pendingRerouteConfirmation را فعال می‌کند
- direction جدید فقط پس از انتخاب مثبت کاربر فراخوانی می‌شود

## ۴. استقلال منطق محصول از Provider خاص

UI و منطق feature نباید مستقیماً به NeshanApi یا ParsimapApi وابسته باشند.

در v1:
- MapService interface وجود دارد
- mapServiceProvider سرویس فعال را ارائه می‌کند
- UI از abstraction مصرف می‌کند

## ۵. حریم خصوصی و حداقل‌سازی داده

فقط داده لازم برای قابلیت درخواست‌شده باید به سرویس خارجی ارسال شود. تنظیمات محلی در SharedPreferences ذخیره می‌شوند. مسیرها و موقعیت برای Search/Direction/Reverse در صورت استفاده به Provider نقشه ارسال می‌شوند؛ این جریان باید در Privacy Policy نهایی شفاف شود.

## اصول تکمیلی

### طراحی Driver-Safe
اطلاعات حیاتی برجسته و تعاملات حین رانندگی حداقلی باشند.

### شفافیت خطا
Silent failure برای عملیات مهم مجاز نیست؛ خطا باید قابل‌فهم به UI برسد.

### کنترل کاربر
Voice، زبان، تم، RouteType و reroute باید تحت کنترل کاربر باشند.

### شواهد قبل از PASS
Build-PASS، Unit-PASS، Device-PASS و Live-API-PASS چهار مفهوم جدا هستند و نباید با هم یکی گرفته شوند.
