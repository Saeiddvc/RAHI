# راهنمای تجربه کاربری (UX) — راهی

## ۱. اصول کلی

1. **سادگی قبل از قدرت:** کاربر باید سریع بفهمد کجاست و اقدام اصلی چیست.
2. **حرکات روان:** هدف انیمیشن‌ها ۲۰۰ تا ۳۰۰ میلی‌ثانیه است.
3. **بازخورد فوری:** هر تعامل باید پاسخ بصری روشن داشته باشد.
4. **زبان طبیعی و کوتاه:** متن‌های حین رانندگی باید مختصر باشند.
5. **RTL/LTR واقعی:** فارسی و عربی RTL؛ انگلیسی LTR.
6. **عدم جعل وضعیت:** نبود سرویس یا داده باید صریح نمایش داده شود.

## ۳. تایپوگرافی

- خانواده هدف: Vazirmatn
- اندازه پایه: 14sp
- عنوان صفحه: حدود 20sp Bold
- زیرعنوان: حدود 16sp Medium
- متن maneuver: حدود 15sp
- تا قبل از Commit assets، fallback فونت سیستم ممکن است فعال باشد

## ۴. جریان‌های اصلی

### جریان ۱: جستجو و مسیریابی

صفحه اصلی → نوار جستجو → Bottom Sheet → تایپ با debounce حدود 400ms → نتایج → انتخاب مقصد → Direction → چند مسیر → کارت مسیر.

### جریان ۲: انتخاب مسیر جایگزین

چند مسیر روی نقشه → FAB مسیرها → Bottom Sheet مسیرها → انتخاب → تغییر مسیر برجسته + Info Card + Zoom.

### جریان ۳: شروع ناوبری

Route Info → شروع → Navigation Screen → maneuver banner → remaining distance/time → TTS در صورت فعال بودن → FAB فهرست گام‌ها.

### جریان ۴: خروج از مسیر

فاصله بیش از 50m از polyline → وضعیت Off Route → اگر 6 ثانیه ادامه داشت Dialog تأیید → «بله» محاسبه مسیر جدید → «نه» عدم تکرار تا بازگشت به مسیر و خروج مجدد.

## ۵. الگوهای تعامل

- Bottom Sheet: جستجو، مسیرها، گام‌های باقی‌مانده
- FAB: موقعیت من، مسیرهای جایگزین، فهرست گام‌ها
- AlertDialog: تصمیم‌های مهم مانند reroute
- SnackBar: خطاهای کوتاه و actionable
- Loading indicator: محاسبه reroute

## ۶. دسترس‌پذیری

- هدف حداقل ناحیه لمس: 48dp
- هدف کنتراست: WCAG AA
- Tooltip روی کنترل‌های آیکونی
- Semantics باید در مرحله Polish نهایی بازبینی شود

## ۷. راهنمای صوتی

- آستانه پیش‌اعلام: 250m
- آستانه عبور maneuver: 30m
- ضدتکرار VoiceService: 8s
- زبان TTS بر اساس زبان UI
- fallback به en-US فقط در صورت عدم پشتیبانی زبان انتخابی و پشتیبانی fallback
- کیفیت فارسی/عربی و timing واقعی هنوز Device-Test نشده است
